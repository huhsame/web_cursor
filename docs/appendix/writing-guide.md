# 📝 AI 코딩 강의 교재 작성 지침

이 문서는 **비개발자 대상 AI 코딩 강의 교재**를 작성할 때 참고할 지침입니다.

---

## 1. 대상자 고려

### 타겟
- **비개발자, 직장인** 대상
- 코딩 경험 전무
- "AI가 대신 코딩해준다"는 관점으로 접근

### 원칙
- 전문 용어 사용 시 **반드시 쉬운 설명** 추가
- 비유와 예시를 적극 활용 (엑셀 시트 = 테이블, 행 = row 등)
- "몰라도 된다"는 안심 멘트 자주 넣기
- 선택적 심화 내용은 `(선택)` 또는 `> 이 섹션은 건너뛰어도 됩니다!`로 표시

---

## 2. 프로젝트 선정

### 기준
- 타겟에게 **실용적인 프로젝트** 선택
- 직장인 → 가계부, 일정관리, 메모장 등
- 학생 → Todo, 시간표, 스터디 그룹 등

### 난이도 구성
| 순서 | 프로젝트 | 난이도 | 교육 방식 |
|------|---------|--------|----------|
| 1번째 | 단순한 앱 (가계부) | 쉬움 | Plan 모드로 한번에 |
| 2번째 | 복잡한 앱 (마켓) | 보통 | 단계별 프롬프트 |

---

## 3. AI 프롬프팅 가이드 (필수!)

### 앞부분에 배치
- **AI에게 어떻게 요청해야 하는지**를 강의 초반에 설명
- 좋은 프롬프트 vs 나쁜 프롬프트 예시

### AI 응답 구분법 (핵심!)
수강생이 가장 헷갈리는 부분 → **AI 응답을 어떻게 처리해야 하는지**

```
📦 코드가 나왔을 때
→ 해당 파일에 복사 또는 Apply 버튼

💻 터미널 명령어가 나왔을 때
→ 터미널에서 실행

📖 설명만 나왔을 때
→ 읽고 이해만

🌐 외부 작업이 필요할 때
→ 브라우저에서 직접 작업 (Supabase, GitHub 등)
```

### 에러 처리 가이드
- 에러 메시지 복사 → AI에게 질문하는 방법 설명
- 흔한 에러 유형별 대처법

---

## 4. 교재 구조

### 형식
- `Day/교시` 형식 ❌ → **Chapter 형식** ✅
- 순서대로 번호 매기기 (Chapter 1, 2, 3...)
- Part로 큰 단위 구분

### 각 챕터 구성
```markdown
# Chapter N. 제목

(간단한 소개)

---

## N.1 소제목

### 개념 설명 (필요시)

### AI에게 요청하기
```
프롬프트 내용
```

### 적용하기
1. Apply → Accept
2. 저장

### 테스트하기
1. 확인 방법

### 📝 커밋하기
```
커밋 메시지
```

---

## 다음 챕터에서는
> 다음 내용 미리보기
> 👉 [Chapter N+1. 제목](경로)
```

---

## 5. Git/GitHub 다루기

### 분리해서 설명
| 시점 | 내용 | 깊이 |
|------|------|------|
| 첫 배포 전 | 기본 사용법 | 간단히 (push만) |
| 2번째 프로젝트 | 상세 설명 | 개념, 명령어, 활용 |

### 커밋 습관화
- **각 기능 완성 후 커밋** 유도
- 커밋 메시지 예시 제공
- 커밋 체크포인트를 교재에 명시

---

## 6. 기술 개념 설명

### SQL
- 데이터베이스 연결 전에 **기초 SQL 먼저** 설명
- SELECT, INSERT, UPDATE, DELETE
- 테이블, 행, 열 개념을 엑셀에 비유

### 1:N 관계
- 그림으로 시각화
- 실제 예시 (사용자 → 상품, 상품 → 댓글)

### RLS (Row Level Security)
- "선택" 표시로 건너뛸 수 있게
- 왜 필요한지 간단히만 설명

## 7. OS별 안내

### 기본 원칙
- **Windows 먼저**, Mac은 괄호로 병기
- 단축키, 경로 등 OS마다 다른 것 명시

### 예시
```
저장: Ctrl + S (Mac: Cmd + S)
터미널 열기: Ctrl + ` (Mac: Cmd + `)
```

---

## 8. 스크린샷

### 위치 표시
```markdown
<!-- 스크린샷: 설명 -->
```

### 필요한 스크린샷
- 설치 화면
- UI 결과물
- 에러 화면
- 외부 서비스 설정 (Supabase, Vercel 등)

---

## 9. Docsify 사이트 설정

### 링크 경로
- Docsify는 **docs/ 폴더 기준** 절대 경로 사용
- `chapter2.md` ❌ → `part1/chapter2.md` ✅

### 한글 표 깨짐 방지 (CSS)
```css
.markdown-section table th,
.markdown-section table td {
  white-space: nowrap;
  word-break: keep-all;
}
```

### 필수 파일
- `index.html` - Docsify 설정
- `_sidebar.md` - 사이드바 메뉴
- `.nojekyll` - GitHub Pages용

## 10. 주의사항 체크리스트

### 콘텐츠
- [ ] 전문 용어에 쉬운 설명 추가했나?
- [ ] AI 응답 구분법 설명했나?
- [ ] 에러 처리 방법 설명했나?
- [ ] 각 기능마다 커밋 체크포인트 있나?
- [ ] OS별 차이 명시했나?
- [ ] 스크린샷 위치 표시했나?

### 기술
- [ ] Docsify 링크 경로 맞나?
- [ ] 사이드바 파일명과 실제 파일명 일치하나?
- [ ] 한글 표 CSS 적용했나?

### 구조
- [ ] 첫 프로젝트는 쉽고, 두 번째는 단계별인가?
- [ ] Git 설명이 적절히 분리되어 있나?
- [ ] SQL/DB 개념이 실습 전에 나오나?
