Part 3에 오신 것을 환영합니다! 🎉

이제 AI 개발의 핵심 기술인 **MCP**를 배워봅니다.
MCP를 이해하면 AI의 능력을 10배로 확장할 수 있어요!

---

## 14.1 AI의 한계

### LLM은 무엇을 알까?

ChatGPT, Claude 같은 AI는 **LLM(Large Language Model)**입니다.

> **LLM = 학습된 데이터만 알고 있는 AI**
>
> 학습이 끝난 시점까지의 정보만 알고 있어요.

### 오늘 날씨를 물어보면?

```
사용자: 오늘 서울 날씨 어때?

AI: 오늘 서울 날씨는 맑고 기온은 12도입니다.
    (이건 그냥 지어낸 말입니다! 할루시네이션!)
```

AI는 **실제 날씨를 모릅니다.**
그냥 "그럴듯한 대답"을 지어내는 것뿐이에요.

### 이런 것들도 모릅니다

| 질문 | AI가 모르는 이유 |
|------|-----------------|
| 오늘 날씨 | 실시간 데이터 없음 |
| 내 일정 | 내 캘린더에 접근 불가 |
| 파일 내용 | 내 컴퓨터 접근 불가 |
| 최신 문서 | 학습 이후 정보 없음 |
| 회사 DB | 외부 데이터베이스 접근 불가 |

## 14.2 해결책: 도구 연결

### 외부 도구와 연결하면?

```
사용자: 오늘 서울 날씨 어때?

AI: (날씨 API를 호출해서 실제 데이터를 가져온다)
    → 오늘 서울 날씨는 흐리고 기온은 8도입니다.
    (진짜 정보!)
```

AI가 **외부 도구(API)**와 연결되면
**진짜 정보**를 가져올 수 있습니다!

### 연결할 수 있는 것들

| 도구 | 할 수 있는 것 |
|------|-------------|
| 날씨 API | 실시간 날씨 정보 |
| 캘린더 | 일정 조회/추가 |
| 파일 시스템 | 파일 읽기/쓰기 |
| 개발 문서 | 최신 문서 참조 |
| 데이터베이스 | DB 조회/수정 |
| Figma | 디자인 파일 접근 |
| GitHub | 코드 저장소 관리 |

## 14.3 MCP의 등장

### 문제: 연결 방법이 제각각

예전에는 각 도구마다 **연결 방법이 달랐습니다.**

```
Gmail API → 연결 방법 A
캘린더 API → 연결 방법 B
Slack API → 연결 방법 C
...
```

**모든 도구마다 직접 개발해서 연결해야 했어요.**

### 해결: 표준 프로토콜 MCP

2024년 11월, Claude를 만든 **Anthropic**에서
**MCP(Model Context Protocol)**를 발표했습니다.

> **MCP = AI와 도구를 연결하는 표준 규격**
>
> USB-C처럼 하나의 규격으로 모든 도구를 연결!

### USB-C와 비슷합니다

| 예전 | 지금 (USB-C) |
|------|-------------|
| 아이폰 → 라이트닝 | 모든 기기 → USB-C |
| 갤럭시 → 마이크로 USB | 모든 기기 → USB-C |
| 노트북 → 각자 다름 | 모든 기기 → USB-C |

**MCP도 마찬가지입니다!**

| 예전 | 지금 (MCP) |
|------|-----------|
| Gmail → 전용 연결 | Gmail → MCP |
| Slack → 전용 연결 | Slack → MCP |
| Notion → 전용 연결 | Notion → MCP |

**하나의 표준으로 모든 도구를 연결!**

## 14.4 MCP 구조 이해하기

### 세 가지 구성요소

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  MCP Client │ ←→  │  MCP Server │ ←→  │    도구     │
│  (AI 앱)    │     │  (중간 다리) │     │ (API/DB 등) │
└─────────────┘     └─────────────┘     └─────────────┘
    Cursor           Context7 MCP        Next.js 문서
    Claude           Supabase MCP        데이터베이스
    VS Code          Figma MCP           디자인 파일
```

### 각 역할

| 구성요소 | 역할 | 예시 |
|---------|------|------|
| **MCP Client** | AI가 있는 앱 | Cursor, Claude Desktop |
| **MCP Server** | 도구와 연결해주는 중간 다리 | Context7, Supabase MCP |
| **도구** | 실제 기능을 제공 | API, DB, 파일 등 |

### 프로토콜이란?

> **프로토콜 = 약속된 형식**

우편을 보낼 때도 약속이 있죠:
- 보내는 사람 → 왼쪽 상단
- 받는 사람 → 오른쪽 하단
- 우표 → 오른쪽 상단

MCP도 마찬가지로 **"이렇게 소통하자"**는 약속입니다.
형식만 맞추면 어떤 도구든 AI와 연결할 수 있어요!

## 14.5 MCP 활용 사례

### 사례 1: 블렌더 3D

**블렌더** = 3D 제작 도구 (애니메이션, 게임 등에 사용)

```
사용자: 이 이미지처럼 3D 오브젝트 만들어줘 (이미지 첨부)

AI: (블렌더 MCP를 통해 블렌더를 직접 조작)
    → 3D 오브젝트 완성!
```

**도구 사용법을 몰라도 AI가 대신 조작합니다!**

<!-- 스크린샷: 블렌더 MCP 데모 -->

### 사례 2: 개발 문서 참조

```
사용자: Next.js 15에서 새로 바뀐 문법으로 코드 짜줘

AI: (Context7 MCP로 최신 문서 확인)
    → 최신 문법으로 코드 작성!
```

**학습되지 않은 최신 정보도 참조 가능!**

### 사례 3: 데이터베이스 조작

```
사용자: 지난 일주일간 신규 가입자 수 알려줘

AI: (Supabase MCP로 DB 조회)
    → 지난 7일간 신규 가입자는 127명입니다.
```

**실제 데이터베이스에서 정보를 가져옵니다!**

### 사례 4: 디자인 확인

```
사용자: Figma에 있는 로그인 페이지 디자인대로 구현해줘

AI: (Figma MCP로 디자인 파일 확인)
    → 디자인과 동일한 코드 생성!
```

**디자인 파일을 직접 확인하고 코드 작성!**

## 14.7 MCP를 쓰면 뭐가 좋아요?

### Before MCP (예전)

```
1. 최신 문서 직접 검색
2. 복사해서 AI에게 붙여넣기
3. AI가 답변
4. 다른 정보 필요하면 다시 1번부터...
```

**번거롭고 시간이 오래 걸림!**

### After MCP (지금)

```
1. AI에게 질문
2. AI가 알아서 MCP로 정보 가져옴
3. 바로 답변!
```

**AI가 알아서 필요한 정보를 가져옵니다!**

### 실제 개발에서의 차이

| 상황 | Before | After MCP |
|------|--------|-----------|
| 최신 문법 확인 | 공식 문서 검색 → 복붙 | AI가 알아서 확인 |
| DB 스키마 확인 | Supabase 접속 → 확인 | AI가 알아서 확인 |
| 디자인 확인 | Figma 접속 → 확인 | AI가 알아서 확인 |
