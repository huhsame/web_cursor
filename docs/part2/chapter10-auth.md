# Chapter 10. 사용자 인증

이번 챕터에서는 **회원가입**과 **로그인** 기능을 만듭니다.

---

## 10.1 인증이란?

### 쉽게 말하면

> **"너 누구야?"를 확인하는 것**입니다.

```
로그인 = 본인 확인
로그아웃 = 확인 해제
```

### 왜 필요한가요?

| 로그인 없을 때 | 로그인 있을 때 |
|--------------|--------------|
| 누가 글 썼는지 모름 | 작성자 표시 가능 |
| 아무나 수정/삭제 | 본인만 수정/삭제 |
| 개인화 불가능 | 내 상품, 내 댓글 관리 |

---

## 10.2 Supabase 인증 설정

### Step 1: 이메일 인증 확인

1. Supabase 대시보드 접속
2. **Authentication** 메뉴 클릭
3. **Providers** 탭 클릭
4. **Email** 이 활성화되어 있는지 확인

<!-- 스크린샷: Email Provider 설정 -->

### Step 2: 이메일 확인 비활성화 (개발용)

개발할 때는 이메일 확인 과정이 번거로우니 끄겠습니다.

1. **Authentication** → **Providers** → **Email**
2. **Confirm email** 옵션을 **OFF**로 변경
3. **Save** 클릭

<!-- 스크린샷: Confirm email OFF -->

> ⚠️ **실제 서비스에서는 ON으로 해야 합니다!**
> 지금은 개발 편의를 위해 끄는 것입니다.

## 10.3 회원가입 페이지 만들기

### AI에게 요청하기

```
회원가입 페이지를 만들어줘.
(app/signup/page.tsx)

입력 필드:
- 이메일 (필수)
- 비밀번호 (필수, 6자 이상)
- 비밀번호 확인 (필수)
- 닉네임 (필수)

기능:
- 비밀번호와 비밀번호 확인이 일치하는지 검증
- Supabase Auth로 회원가입
- 회원가입 시 닉네임도 메타데이터로 저장
- 성공하면 메인 페이지로 이동
- 에러 시 메시지 표시 (이미 가입된 이메일 등)

'use client' 사용
TypeScript + Tailwind
깔끔한 폼 디자인
```

### 적용하기

1. Apply → Accept
2. 저장

### 헤더에 링크 추가

```
app/layout.tsx 헤더를 수정해줘.

로그인 안 한 상태:
- "로그인" 버튼 → /login
- "회원가입" 버튼 → /signup

아직 로그인 상태 체크는 하지 마.
일단 버튼만 추가해줘.
```

### 테스트하기

1. 회원가입 페이지 접속 (`localhost:3000/signup`)
2. 정보 입력 후 가입
3. Supabase 대시보드 → **Authentication** → **Users** 확인
4. 새 사용자가 등록되어 있으면 성공!

## 10.5 로그인 상태 관리하기

### 현재 문제

로그인해도 헤더가 안 바뀝니다.
로그인 상태를 확인하는 기능이 없기 때문입니다.

### AI에게 요청하기

```
로그인 상태를 관리하는 AuthContext를 만들어줘.
(app/contexts/AuthContext.tsx)

기능:
- 현재 로그인한 사용자 정보 저장
- 로그인 상태 변경 감지 (onAuthStateChange)
- 앱 전체에서 사용 가능하게 Context로

그리고 app/layout.tsx에서 AuthProvider로 감싸줘.
```

### 헤더 수정하기

```
app/layout.tsx 헤더를 수정해줘.

로그인 상태에 따라 다르게 표시:

로그인 안 함:
- "로그인" 버튼
- "회원가입" 버튼

로그인 함:
- "상품 등록" 버튼
- 사용자 닉네임 표시
- "로그아웃" 버튼

AuthContext의 user 정보 사용
```

### 적용 및 테스트

1. 모든 파일 Apply → Accept → 저장
2. 로그아웃 상태에서 헤더 확인
3. 로그인 후 헤더가 바뀌는지 확인
4. 로그아웃 버튼이 동작하는지 확인

<!-- 스크린샷: 로그인 전 헤더 -->
<!-- 스크린샷: 로그인 후 헤더 -->

### 📝 커밋하기

```
로그인 상태 관리 및 헤더 업데이트
```

## 10.6 상품 등록에 사용자 연결하기

### 현재 문제

상품 등록할 때 user_id가 비어있습니다.

### AI에게 요청하기

```
상품 등록 페이지(app/products/new/page.tsx)를 수정해줘.

- 로그인 안 한 상태면 로그인 페이지로 리다이렉트
- 상품 저장할 때 user_id에 현재 로그인한 사용자 ID 넣기
- AuthContext 사용
```

### 적용 및 테스트

1. Apply → Accept → 저장
2. 로그아웃 상태에서 /products/new 접속 시도
3. 로그인 페이지로 이동하는지 확인
4. 로그인 후 상품 등록
5. Supabase에서 user_id가 채워졌는지 확인

### 📝 커밋하기

```
상품 등록에 사용자 연결
```

## 10.7 본인 상품만 수정/삭제 가능하게

### AI에게 요청하기

```
상품 상세 페이지(app/products/[id]/page.tsx)를 수정해줘.

- 수정/삭제 버튼은 본인 상품일 때만 보이게
- 현재 로그인한 사용자 ID와 상품의 user_id 비교
- AuthContext 사용
```

### 상품 수정 페이지도 보호

```
상품 수정 페이지(app/products/[id]/edit/page.tsx)를 수정해줘.

- 본인 상품이 아니면 상세 페이지로 리다이렉트
- 로그인 안 했으면 로그인 페이지로 리다이렉트
```

### 적용 및 테스트

1. Apply → Accept → 저장
2. 다른 사람 상품에서 수정/삭제 버튼이 안 보이는지 확인
3. URL 직접 입력으로 수정 페이지 접근 시도
4. 리다이렉트 되는지 확인

### 📝 커밋하기

```
본인 상품만 수정/삭제 가능하게 수정
```

## 10.8 상세 페이지에 판매자 정보 표시

### AI에게 요청하기

```
상품 상세 페이지에서 판매자 정보를 표시해줘.

- 판매자 닉네임 표시
- products 테이블 조회할 때 profiles 테이블 조인
- Supabase의 select로 관계 데이터 가져오기

예시:
const { data } = await supabase
  .from('products')
  .select('*, profiles(nickname)')
  .eq('id', id)
  .single()
```

### 적용 및 테스트

1. Apply → Accept → 저장
2. 상세 페이지에서 판매자 닉네임이 보이는지 확인

### 📝 커밋하기

```
상세 페이지에 판매자 정보 추가
```

## 핵심 정리

```
✅ 인증 = 사용자 확인 (로그인/로그아웃)
✅ Supabase Auth = 인증 기능 제공
✅ Context = 앱 전체에서 상태 공유
✅ 본인 확인 = user_id 비교
✅ 보호된 페이지 = 로그인 필요
```
