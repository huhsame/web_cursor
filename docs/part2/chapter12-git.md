## 12.1 Git이 왜 필요한가요?

### 상황 1: 실수로 코드를 망쳤다

```
어제까지 잘 되던 코드가...
이것저것 수정하다가 망가졌다!
어디서부터 잘못됐는지 모르겠다 😱
```

**Git이 있다면:**
```
git으로 어제 상태로 되돌리기!
문제 해결 😎
```

### 상황 2: 여러 버전을 관리하고 싶다

```
가계부_최종.zip
가계부_최종_진짜최종.zip
가계부_최종_진짜최종_수정.zip
가계부_이게진짜최종.zip
```

**Git이 있다면:**
```
커밋 1: 기본 기능
커밋 2: 디자인 수정
커밋 3: 버그 수정
...
깔끔하게 버전 관리!
```

### 상황 3: 여러 명이 함께 작업

```
A: "내가 수정한 파일 줄게"
B: "나도 그 파일 수정했는데..."
A: "그럼 누구 걸 쓰지?"
```

**Git이 있다면:**
```
각자 수정하고 합치기 가능!
충돌도 해결 가능!
```

## 12.2 Git 핵심 개념

### 저장소 (Repository)

> **Git으로 관리되는 프로젝트 폴더**입니다.

```
my-project/
├── .git/         ← Git 정보 저장 (숨김 폴더)
├── app/
├── package.json
└── ...
```

`.git` 폴더가 있으면 Git 저장소입니다.

### 로컬 vs 원격

| 로컬 저장소 | 원격 저장소 |
|------------|------------|
| 내 컴퓨터에 있음 | 인터넷에 있음 |
| 나만 접근 가능 | 팀원들도 접근 가능 |
| 예: 내 프로젝트 폴더 | 예: GitHub |

```
내 컴퓨터 (로컬)          GitHub (원격)
┌─────────────┐          ┌─────────────┐
│ my-project  │ ──push──▶│ my-project  │
│             │◀──pull── │             │
└─────────────┘          └─────────────┘
```

## 12.3 Git 상태 이해하기

### 파일의 3가지 상태

```
Working Directory    Staging Area       Repository
   (작업 공간)          (대기 장소)          (저장소)
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  수정된 파일  │─add─▶│  준비된 파일  │─commit─▶│  저장된 버전  │
└─────────────┘     └─────────────┘     └─────────────┘
```

1. **Working Directory** - 파일을 수정한 상태
2. **Staging Area** - 커밋할 파일을 선택한 상태
3. **Repository** - 커밋으로 저장된 상태

### 예시

```bash
# 1. 파일 수정 (Working Directory)
#    page.tsx 파일을 수정함

# 2. 스테이징 (Staging Area)
git add page.tsx
#    "이 파일 커밋할 거야"

# 3. 커밋 (Repository)
git commit -m "메인 페이지 수정"
#    "저장 완료!"
```

## 12.4 자주 쓰는 Git 명령어

### 상태 확인

```bash
git status
```

현재 상태를 보여줍니다:
- 수정된 파일
- 스테이징된 파일
- 커밋 안 된 변경사항

<!-- 스크린샷: git status 결과 -->

### 변경사항 보기

```bash
git diff
```

뭐가 바뀌었는지 보여줍니다:
- 🟢 초록색 = 추가된 내용
- 🔴 빨간색 = 삭제된 내용

### 스테이징

```bash
# 특정 파일만
git add 파일명

# 모든 변경 파일
git add .
```

### 커밋

```bash
git commit -m "커밋 메시지"
```

### 히스토리 보기

```bash
git log
```

지금까지의 커밋 기록을 보여줍니다.

```bash
git log --oneline
```

한 줄로 간단하게 보여줍니다.

## 12.5 커서에서 Git 사용하기

### Source Control 패널

1. 왼쪽 사이드바에서 **Source Control** 아이콘 클릭
   (가지 모양 아이콘)

<!-- 스크린샷: Source Control 아이콘 -->

2. 변경된 파일 목록이 보입니다

<!-- 스크린샷: 변경 파일 목록 -->

### 스테이징하기

- 파일 옆 **+** 버튼 클릭 = 해당 파일만 스테이징
- 상단 **+** 버튼 클릭 = 모든 파일 스테이징

<!-- 스크린샷: 스테이징 버튼 -->

### 커밋하기

1. 메시지 입력창에 커밋 메시지 작성
2. **✓ 체크** 버튼 클릭 (또는 `Ctrl/Cmd + Enter`)

<!-- 스크린샷: 커밋하기 -->

### 푸시하기

1. **...** 메뉴 클릭
2. **Push** 선택

또는 하단 상태바에서 **동기화** 아이콘 클릭

<!-- 스크린샷: 푸시하기 -->

## 12.6 좋은 커밋 메시지 작성법

### 나쁜 예시

```
ㅇㅇ
수정
asdf
버그 고침
작업중
```

### 좋은 예시

```
회원가입 페이지 추가
로그인 버그 수정 - 이메일 검증 오류
상품 목록 무한 스크롤 구현
헤더 반응형 디자인 적용
```

### 규칙

1. **한글로 써도 됩니다**
2. **뭘 했는지 명확하게**
3. **너무 길지 않게** (한 줄)
4. **하나의 커밋 = 하나의 작업**

## 12.7 되돌리기

### 아직 커밋 안 한 변경 되돌리기

```bash
# 특정 파일 되돌리기
git checkout -- 파일명

# 모든 변경 되돌리기
git checkout -- .
```

### 커서에서 되돌리기

1. Source Control 패널에서 파일 우클릭
2. **Discard Changes** 클릭

<!-- 스크린샷: Discard Changes -->

### 커밋 후 되돌리기

```bash
# 직전 커밋 취소 (변경사항은 유지)
git reset --soft HEAD~1

# 직전 커밋 취소 (변경사항도 삭제) ⚠️
git reset --hard HEAD~1
```

> ⚠️ `--hard`는 조심해서 사용하세요!
> 변경사항이 완전히 사라집니다!

## 12.8 브랜치 (선택)

### 브랜치란?

> **독립적인 작업 공간**입니다.

```
main 브랜치 ─────●─────●─────●─────●
                         ╲
feature 브랜치            ●─────●
                              (새 기능 개발)
```

- `main` = 안정적인 코드
- `feature` = 새 기능 개발 중

### 브랜치 만들기

```bash
# 새 브랜치 만들고 이동
git checkout -b 브랜치명
```

### 브랜치 이동

```bash
git checkout 브랜치명
```

### 브랜치 합치기

```bash
# main 브랜치로 이동
git checkout main

# feature 브랜치 합치기
git merge feature
```

## 12.9 실수했을 때 대처법

### "push 했는데 잘못됐어요"

```
이미 GitHub에 올린 건 되돌리기 어렵습니다.
새로운 커밋으로 수정하세요.
```

### "merge 충돌이 났어요"

```
충돌된 파일을 열면:
<<<<<<< HEAD
내 코드
=======
다른 사람 코드
>>>>>>> branch-name

둘 중 하나를 선택하거나 합치고 저장!
```

### "뭘 해야 할지 모르겠어요"

```bash
git status
```

Git이 뭘 해야 하는지 알려줍니다!

## 12.10 .gitignore 파일

### 무시할 파일 설정

`.gitignore` 파일에 적힌 파일/폴더는 Git이 무시합니다.

```
# .gitignore 예시

node_modules/
.env.local
.env
.DS_Store
```

### 왜 필요한가요?

| 무시해야 할 것 | 이유 |
|--------------|------|
| node_modules/ | 용량 크고, npm install로 생성 |
| .env.local | 비밀 정보 포함 |
| .DS_Store | Mac 시스템 파일 |
