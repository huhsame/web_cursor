# Day 1 - 2교시: 웹이 동작하는 원리 이해하기

## 학습 목표
- 웹사이트가 어떻게 동작하는지 이해한다
- 프론트엔드와 백엔드의 차이를 안다
- 클라이언트-서버 모델을 이해한다
- 우리가 사용할 기술들의 역할을 파악한다

---

## 1. 웹은 어떻게 동작할까?

### 쉬운 설명
> 식당을 상상해보세요.
>
> 1. **손님(클라이언트)**: 메뉴를 보고 주문합니다
> 2. **웨이터(인터넷)**: 주문을 주방에 전달합니다
> 3. **주방(서버)**: 요리를 만듭니다
> 4. **냉장고(데이터베이스)**: 재료를 보관합니다
>
> 웹도 똑같습니다!
> - 손님 = 여러분의 브라우저
> - 웨이터 = 인터넷
> - 주방 = 서버
> - 냉장고 = 데이터베이스

### 공식적인 설명
```
웹은 클라이언트-서버 아키텍처를 기반으로 합니다.
클라이언트(브라우저)가 HTTP 프로토콜을 통해
서버에 요청(Request)을 보내면,
서버는 해당 요청을 처리하고
응답(Response)을 반환합니다.
```

### 그림으로 보기

```
  👤 사용자                    🌐 인터넷                   🖥️ 서버
     │                          │                         │
     │  1. 주소 입력              │                         │
     │  (naver.com)             │                         │
     │─────────────────────────▶│                         │
     │                          │  2. 요청 전달             │
     │                          │────────────────────────▶│
     │                          │                         │
     │                          │                    3. 처리
     │                          │                    (DB 조회 등)
     │                          │                         │
     │                          │  4. HTML/데이터 응답      │
     │                          │◀────────────────────────│
     │  5. 화면 표시              │                         │
     │◀─────────────────────────│                         │
     │                          │                         │
  [브라우저]                                            [컴퓨터]
```

## 2. 프론트엔드 vs 백엔드

### 쉬운 설명

| 구분 | 프론트엔드 | 백엔드 |
|------|-----------|--------|
| **뜻** | 앞쪽(Front) | 뒤쪽(Back) |
| **비유** | 식당 홀 | 주방 |
| **역할** | 보이는 부분 | 안 보이는 부분 |
| **담당** | 화면, 버튼, 디자인 | 데이터 처리, 저장 |

### 공식적인 설명

**프론트엔드 (Frontend)**
```
사용자 인터페이스(UI)를 담당하는 영역입니다.
HTML, CSS, JavaScript를 사용하여
사용자가 보고 상호작용하는 화면을 만듭니다.
React, Vue, Angular 등의 프레임워크를 사용합니다.
```

**백엔드 (Backend)**
```
서버 측 로직을 담당하는 영역입니다.
데이터베이스 연동, 비즈니스 로직 처리,
API 제공, 인증/보안 등을 담당합니다.
Node.js, Python, Java 등의 언어를 사용합니다.
```

### 실제 예시: 인스타그램

```
[프론트엔드가 하는 일]
- 피드 화면 보여주기
- 좋아요 버튼 누르면 하트 색 바꾸기
- 스크롤하면 새 게시물 로딩
- 예쁜 필터 효과 적용

[백엔드가 하는 일]
- 내 계정 정보 저장
- 팔로워/팔로잉 관계 관리
- 게시물 데이터 저장
- 좋아요 수 계산
- 알림 보내기
```

## 3. 웹 기술 3형제: HTML, CSS, JavaScript

### 쉬운 설명

> 집을 짓는다고 생각해보세요.
>
> - **HTML**: 뼈대 (벽, 문, 창문)
> - **CSS**: 인테리어 (페인트, 가구, 조명)
> - **JavaScript**: 기능 (전등 스위치, 초인종)

### 각각의 역할

**HTML (HyperText Markup Language)**
```html
<!-- 웹페이지의 구조를 만듭니다 -->
<h1>안녕하세요</h1>
<p>저는 홍길동입니다.</p>
<button>클릭하세요</button>
```

**CSS (Cascading Style Sheets)**
```css
/* 예쁘게 꾸밉니다 */
h1 {
  color: blue;
  font-size: 24px;
}

button {
  background-color: green;
  border-radius: 8px;
}
```

**JavaScript**
```javascript
// 동작을 추가합니다
button.addEventListener('click', function() {
  alert('버튼을 클릭했습니다!');
});
```

### 코드 없이 설명하면

```
HTML = "여기에 버튼이 있어"
CSS = "그 버튼은 파란색이고 둥글어"
JavaScript = "버튼 누르면 알림창 떠"
```

## 4. 데이터베이스란?

### 쉬운 설명

> 데이터베이스는 **엑셀 시트**와 비슷합니다.
>
> 정보를 표 형태로 저장하고,
> 필요할 때 찾아서 사용합니다.

### 엑셀과 비교

**엑셀 시트:**
| 이름 | 나이 | 이메일 |
|------|------|--------|
| 김철수 | 25 | kim@email.com |
| 이영희 | 30 | lee@email.com |

**데이터베이스 (테이블):**
```sql
users 테이블
┌────┬────────┬─────┬─────────────────┐
│ id │  name  │ age │     email       │
├────┼────────┼─────┼─────────────────┤
│  1 │ 김철수  │  25 │ kim@email.com   │
│  2 │ 이영희  │  30 │ lee@email.com   │
└────┴────────┴─────┴─────────────────┘
```

### 공식적인 설명
```
데이터베이스(Database)는 구조화된 데이터의 집합입니다.
DBMS(Database Management System)를 통해
데이터의 저장, 검색, 수정, 삭제를 관리합니다.
SQL(Structured Query Language)을 사용하여
데이터를 조작합니다.
```

### CRUD - 데이터의 4가지 기본 동작

| 영어 | 한글 | 설명 | SQL |
|------|------|------|-----|
| **C**reate | 생성 | 새 데이터 추가 | INSERT |
| **R**ead | 읽기 | 데이터 조회 | SELECT |
| **U**pdate | 수정 | 데이터 변경 | UPDATE |
| **D**elete | 삭제 | 데이터 제거 | DELETE |

┌─────────────────────────────────────────────────────────────┐

### 각 기술 쉽게 설명

**Next.js**
> 레고 블록 세트라고 생각하세요.

> 마치 유튜브에 영상 올리면 전세계에서 볼 수 있는 것처럼!

**Git/GitHub**
> 코드의 타임머신이에요.
> 언제든 과거 버전으로 돌아갈 수 있고,
> 여러 사람이 함께 작업할 수 있게 해줘요.

## 6. API란?

### 쉬운 설명

> 식당의 **메뉴판**이라고 생각하세요.
>
> 메뉴판에는 "이렇게 주문하면 이런 음식이 나옵니다"라고
> 적혀있죠?
>
> API도 마찬가지입니다.
> "이렇게 요청하면 이런 데이터를 줄게요"라고
> 약속된 규칙이에요.

### 실제 예시

```
[네이버 날씨 API 예시]

요청: "서울 날씨 알려줘"
GET /weather?city=seoul

응답:
{
  "city": "서울",
  "temperature": 23,
  "condition": "맑음"
}
```

### 공식적인 설명
```
API(Application Programming Interface)는
소프트웨어 간의 통신 방법을 정의한 인터페이스입니다.
REST API는 HTTP 메서드(GET, POST, PUT, DELETE)를
사용하여 자원을 조작하는 아키텍처 스타일입니다.
```

## 7. 실습: 웹 동작 직접 보기

### 실습 1: 개발자 도구 열어보기

1. 크롬 브라우저에서 아무 사이트 열기
2. `F12` 또는 `Cmd/Ctrl + Shift + I` 누르기
3. **Network** 탭 클릭
4. 새로고침 (`F5`)

**볼 것:**
- 수많은 요청(Request)들이 오가는 것
- HTML, CSS, JS, 이미지 파일들
- 각 요청의 응답 시간

### 실습 2: HTML 구조 보기

1. 개발자 도구에서 **Elements** 탭 클릭
2. 왼쪽 위 화살표 아이콘 클릭
3. 웹페이지의 아무 곳이나 클릭

**볼 것:**
- HTML 태그들의 구조
- 각 요소에 적용된 CSS

### 실습 3: API 응답 보기

1. 브라우저 새 탭 열기
2. 주소창에 입력: `https://jsonplaceholder.typicode.com/users/1`
3. 엔터

**볼 것:**
```json
{
  "id": 1,
  "name": "Leanne Graham",
  "username": "Bret",
  "email": "Sincere@april.biz"
  ...
}
```

이것이 바로 API 응답입니다!

## 핵심 정리

```
✅ 웹 = 클라이언트(브라우저)와 서버의 대화
✅ 프론트엔드 = 보이는 부분 (화면)
✅ 백엔드 = 안 보이는 부분 (데이터 처리)
✅ HTML(구조) + CSS(스타일) + JS(동작)
✅ 데이터베이스 = 데이터를 저장하는 창고
✅ API = 서버와 대화하는 규칙
```

## 용어 정리

| 용어 | 뜻 |
|------|-----|
| 클라이언트 | 서비스를 요청하는 쪽 (브라우저) |
